## 3. 两条路线

### 路线 1（推荐先试）：fl2va ＋ Fun ControlNet，用深度或轮廓视频控制动作

- 首帧放牛来待机图（绿底，768×768），负责长相；ControlNet 输入白模控制视频，逐帧约束动作。
- **控制视频必须包含剑**：深度图或轮廓（Canny）视频里有剑；SDPose 骨骼没有剑，挥砍轨迹会丢，**不要只用 pose**。
- 优点：只需要下载 2.3GB，磁盘够；动作还原度最高，剑的轨迹受约束，有望消除灰色弯月拖影。
- 风险：白模是成人比例，牛来矮胖，深度或轮廓会把牛来往人形拉。缓解办法见 4.1。
- 前提：**升级 ComfyUI 到 ≥ 0.35**，升级后核对实际节点名，例如 `Apply MiniMax H3 Fun ControlNet`，用法参照官方模板 `video_minimax_h3_fun_controlnet_union.json`。

### 路线 2（备选）：Ref2VA 参考生视频

- 用 `MiniMaxH3ReferenceToVideo` 输入 `<Picture 1>` 牛来参考图和 `<Video 1>` 白模片段。提示词写明 Picture 1 决定角色外观，Video 1 决定动作和机位。这跟教程里 Seedance 的做法最接近。
- 优点：对体型差异比较宽容；现有 ComfyUI 版本就有这个节点。
- 缺点：要 19.5GB 主模型，D 盘**空间不够**；动作是“参考”，不是逐帧锁定；参考视频至少 2 秒。
- 如果路线 1 体型问题解决不了就切到这里。也可以 Ref2VA ＋ ControlNet 一起用。

## 4. 执行步骤（路线 1）

### 4.1 准备控制视频（Blender，不占显卡，不需要用户审批）

- 输入：`outputs/motion_reference_20261015/ual2_review.blend`（`prepare_blend.py` 已经把剑绑到手骨上，并设置了 `Sword_Heavy_Combo`）。
- Blender：`D:/Program Files/Blender Foundation/Blender 5.2/blender.exe --background --python <脚本>`
- 新写脚本 `tools/render_control_heavy_combo.py`，输出到新目录 `art_source/control/heavy_combo_v01/`：
  - 只保留**一个**白模，不要用左右双人的评审版。正交纯侧视，面朝右，24fps，768×768，纯色背景。
  - 白模和剑的位置、大小要对齐牛来的标准画布：脚底在 y=208×3=624，身体中心 x≈112×3=336，站立身高约 64×3=192 像素，剑长对齐 `niulai_idle_tail_native.png` 里的剑。
  - 导出 `depth/`（归一化深度）、`lineart/`（轮廓或 Canny）、`beauty/`（灰模）三套 PNG 序列和对应 MP4。
  - **体型缓解**：另外导出一版“牛来比例代理”，即在骨骼上缩短腿和躯干、放大头部，与原比例版做对比。
- 自检：帧数等于动作帧数；第 0 帧和牛来待机图叠在一起，脚底、身体中心、握剑点大致重合。

### 4.2 准备首帧

- 首帧用 `art_source/reference/poses/niulai_idle_tail_native.png`，按最近邻放大 3 倍，垫纯绿底。参考 `tools/run_h3_heavy_segments.py` 里的 `green_canvas()`。
- 如果白模第 0 帧和牛来待机姿势差太多，以对齐控制视频为准，不要让模型在第一秒跳姿势。

### 4.3 生成试验（需要用户先同意 ComfyUI 升级和下载）

- 新脚本 `tools/run_h3_control_heavy.py`，接口按 `tools/comfy_minimax.py` 的 `api/upload` 写。每次试验单独一个目录：`art_source/minimax/heavy_combo_ctrl_v01_<变体>/`，保留 `job.json`、`prompt.txt`、`workflow_api.json`、`history.json`，**已有 job.json 就跳过**，防止重复提交。
- 第一轮只跑整段连招（105 帧对齐到 107 帧），变体：
  - A：深度，原比例，strength 1.0
  - B：轮廓，原比例，strength 1.0
  - C：效果较好的那种控制，用比例代理
- 每段 turbo 8 步，大约 9–10 分钟。先跑 A，看了再决定要不要跑 B 和 C。
- 提示词：正面描述牛来外观、固定侧视、纯绿背景，剑是同一把刚性直剑。**不要写“不要剑光/火花”**，越写越多（CLAUDE.md 有记录）。

### 4.4 审查

- 用 `tools/review_h3_heavy_segments.py` 的思路（调用 `prep_sprites.py` 的抠绿和像素化函数，不写入 `assets/`）生成原生像素接触表和 GIF。另外做一个**白模和牛来左右并排**的对比视频，方便用户检查动作是否一致。
- 合格标准：
  - 动作和白模逐段一致：下撩、斜劈、回扫、砸地、收招。
  - 剑形每帧一致，没有灰色弯月。
  - 脸、尾巴、配色、体型稳定；背景全程纯绿。
  - 抠图后每帧不透明像素数大致稳定（参考值 2600–3000，砸地帧剑贴地会略多）。
- 审查结果写进 `docs/已完成/`，**交给用户确认**以后才能入库。

### 4.5 切段与补收招（路线 1 合格之后）

- 按下面的参考节拍切段（帧号对应 `outputs/motion_reference_20261015/clean_side/ual2__Sword_Heavy_Combo.mp4`，生成结果会有偏移，以实际画面为准）：

| 段 | 参考帧 | 动作 |
| --- | --- | --- |
| 准备 | R000–R006 | 待机 → 剑竖在身前 → 下蹲，剑拉到身后下方 |
| 第 1 刀 | R009–R012 | 从后下方往前下撩/前扫，手臂伸直 |
| 第 2 刀 | R015–R027 | 剑过肩高举 → 弓步斜劈到前下方 |
| 回扫 | R030–R051 | 剑横扫到身后，压低重心蓄住 |
| 第 3 刀 | R054–R063 | 后仰高举 → 砸地重劈 |
| 收招 | R066–R102 | 剑压地长停顿 → 提剑站起 → 待机 |

- 第 1、2 刀中途停手时需要**独立收招**（从该刀结束姿势回到待机）。白模动作库里没有这几段，可以：
  - 在 Blender 里用关键帧混合做白模收招，再按同样方式生成；或者
  - 用 fl2va 首尾帧模式补，首尾帧取自已生成的帧。
- 首尾帧补帧时**至少用 39 帧**。22 帧会出现“原地停住＋残影＋跳回”的淡入淡出效果（分段试验 v01 的教训）。

## 7. 历史经验（不要重复踩坑）

- H3 会自己加剑光和火花，并且会把剑和剑光融成一大片灰色；`prep_sprites.py` 只能去掉偏蓝亮白的剑光，**去不掉灰色弯月**。
- 用定稿像素关键姿势当首尾帧时，剑形明显更稳定（分段试验 cut1）。
- ComfyUI 在 VAE 解码时出现过一次原生崩溃（access violation），重启后重跑成功。日志在 `outputs/h3_heavy_combo_trial/comfy_stderr_crash_cut2.log`。
- ComfyUI 后台启动参数见 `docs/已完成/2026-10-15_H3重连招分段试验v01.md` 的事故一节。用完记得关掉，空闲时也会占约 5GB 显存。
- Python：需要 cv2 的脚本用 `C:/Users/Administrator/AppData/Local/Programs/Python/Python311/python.exe`（同时有 av）；ComfyUI venv 里没有 cv2。
- `outputs/` 被 git 忽略，跨机器转交要另外带上。
